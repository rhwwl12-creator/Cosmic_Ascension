## 6. UE5 기술 아키텍처

### 6.1 모듈 계층 구조

```

[ Presentation Layer (UI & Visuals) ]

├── UMG 위젯 (은하 지도 HUD, 성계 정보 패널, 은하 패널, 로그 피드, 조우 카드, 상단 자원/시간 바)

├── Minimal 3D Viewport (성계 노드 액터, 레인 라인, 성운 배경 셰이더, 배경 별·풍경 은하(그림뿐))

└── Niagara FX (승천 연출, 차원 균열, 초월자 오라) — 3종만

▲ (델리게이트 구독만. UI는 시뮬 상태를 읽기만 하고 명령은 Subsystem 함수 호출)

[ Core Logic Layer (GameInstance Subsystems) ]

├── UGalaxySimulationSubsystem 성계/문명 고정 스텝 틱, 경제·연구·외교·분쟁·위기·AI·건넘·앎 (§7.4)·건넘·앎

├── UCosmicEventSubsystem 조건 평가, 가중치 추첨, 효과 적용, 쿨다운

├── UAscensionSubsystem 업적 조건 감시, 등급 상승, 권능 부여, 승천 연출 트리거

├── UCosmicLogSubsystem 템플릿 치환(PickTemplateRow: 계시 양식 Context, 역할 슬롯·{PopBand} 해석과 집단 폴백), 로그 큐, 이야기의 범위(§8.1), 연대기 집계(생애별 장 + 두 책 장)

├── UPlayerRoleSubsystem 통치자/방랑자 전환, 이동, 조우·청원 진행, 명령 API, 사망·폐위·공백기·계승 파이프라인, 귀환 제안 훅 OfferReturn (§4.4, §5.10)

└── UCosmicSaveSubsystem FGalaxyState ↔ 슬롯(머리·압축·백업), 판당 슬롯 1개, 틱 경계의 자동 저장·입력의 저장·이어하기 (§9.1)

▲

[ Data Layer ]

├── 정의(Definition, 읽기 전용, DataTable): DT_Traits, DT_Events, DT_Feats, DT_Encounters, DT_Relics, DT_Edicts, DT_Megaprojects, DT_Hazards, DT_LogTemplates, DT_Civs, DT_Transcendents, DT_Dedications, DT_Galaxies, DT_Rules

├── 상태(State, 런타임, 저장 대상, USTRUCT): FGalaxyState { Systems, Civs, Transcendents, Player, Calling, Knowing, Transits, Log, Chronicle, Flags, RngState, TellRngState, NextCivSerial, GalaxyID }

└── 문자열: String Table ST_CA (UI), DataTable의 FText 컬럼 (서사)

```

**원칙**

시뮬레이션 코드는 UI와 월드(Actor)를 모른다. Core Logic Layer 폴더(`Sim/`, `Events/`, `Ascension/`, `Log/`, `Player/`, `Save/`) 안의 코드가 `UUserWidget`이나 `AActor`를 include하면 설계 위반이다. 이 규칙은 직접 include와 그 타입의 사용에 대한 것이다 — `Save/`가 `SaveGameToMemory`·`LoadGameFromMemory`(§9.1) 때문에 include하는 `Kismet/GameplayStatics.h`가 끌고 오는 Actor 헤더는 허용되는 전이 경우다.
UI는 Subsystem의 델리게이트를 구독하고 상태를 읽는다. 상태를 직접 수정하지 않는다.
뷰포트의 성계 액터는 상태의 '시각 표현'일 뿐이다. 액터가 없어도 시뮬은 돌아야 한다 (헤드리스 테스트의 전제).
모든 Core Logic Subsystem의 델리게이트 Broadcast는 전역 방송 게이트(`UGalaxySimulationSubsystem::IsBroadcastEnabled()`)를 본다. 공백기 도약(§4.4)과 헤드리스 실행 중에는 게이트가 닫힌다.
Core Logic Subsystem은 플레이어·생애에 종속된 멤버 변수를 갖지 않는다. 지속 업적 진척(`CompletedMegaprojects`, `SealedTick` 등)은 `FGalaxyState` 안에 둔다(§4.4).

### 6.2 Subsystem 선택 근거

모두 `UGameInstanceSubsystem`. 레벨 전환(메뉴 ↔ 은하 맵)에도 상태가 유지된다.
틱은 `FTickableGameObject`를 함께 상속해 받는다. 월드 타이머에 의존하지 않는다.
상태는 Subsystem이 들고 있는 `FGalaxyState` 구조체 하나에 모은다(판의 상태 = 고향 은하 상세 + 판 공통, §7.2). UObject 그래프로 만들지 않는다. 저장이 단순해지고 결정론 검증(해시)이 가능하다.
판 상태는 세 층(세계 → 앎 → 이야기)이고 의존은 한 방향이다: 세계는 앎을 `NoteMet`·`NoteKnown`으로 쓰기만 하고 읽지 않는다(전문과 예외 하나는 §8.1).

### 6.3 UI 기술 선택: UMG 우선

초안은 CommonUI였다. CommonUI의 강점(입력 라우팅, 플랫폼별 액션 바, 패드 포커스)은 PC 싱글 텍스트 게임에서는 거의 쓰이지 않고, 학습 비용과 셋업 비용이 있다.
**결정: UMG + C++ 위젯 베이스 클래스**로 시작한다. 스팀덱/패드 지원을 목표에 넣는 시점에 CommonUI 전환을 재검토한다 (§16).
로그 피드는 `UListView`로 가상화한다. 수천 줄을 Text Block으로 쌓지 않는다.
화면의 패널(Phase 3 3번 작업, WBP 없는 C++ 위젯): 상단 바 `UCosmicTopBarWidget`(통치하는 백성의 이름·칸·안정도 — 제 덩이에 추세 ▲▼와 툴팁, MVP ⑥ 아래 '안정도 추세와 첫 안내' —, 자원 다섯은 정수, 연구 넷은 비율(제 툴팁 — 지금 연구 중점과 네 몫, 빈 줄, 그다음 '다음 칸까지', MVP ⑦), 주기, 배속 단추 — 정지·×1·×2·×5·×10(단추마다 숫자 키의 툴팁, MVP ⑥), 셋째 칸의 문(§6.4 영적 시야와 같은 문 — 보는 쪽 Tier가 셋째 칸 이상)이 열리고 승천 연출이 보이지 않을 때 ×25(툴팁 두 줄 — 숫자 키와 셋째 칸의 배속, 문이 닫히면 흐리지 않고 접힌다), 지금 배속은 흐리게, 셋째 칸부터 시계와 배속 단추 사이의 보기 단추 — §6.4 영적 시야 토글), 오른쪽의 성계 정보 패널 `UCosmicSystemPanelWidget`(선택한 성계가 있을 때만 — 모르는 성계는 고를 수 없고 패널도 없다, §6.4: 이름, 항성 등급, 주인 — 보이는 백성이면 그 이름, 보이지 않는 백성(만나지 않았거나 세 칸 이상 위)이면 '주인  다른 백성', 또는 '주인 없음'·'파괴된 성계' —, 주인이 보이는 백성이면 바로 아래에 그 백성의 규모 등급 한 줄 '{PopBand} 백성'(§8.3 — 무주 성계·파괴된 성계·상태에 없는 주인·보이지 않는 주인에는 없다, 숫자 없음), 그다음 '이 세계의 생명' 한 줄(§5.7 — 살아 있는 아는 성계에, 단계 4까지 `sol`은 빼고), 위기와 남은 주기, 건설·대응 칸의 진척/필요 진척(보이지 않는 주인의 칸은 그 백성의 일이라 없다), 영적 시야에서는 상세 줄 아래 표식의 말 한 줄과 그 툴팁(§6.4 — 상세 줄과 따로라 규모 줄을 덮지 않는다), 그리고 통치자의 명령). 명령 단추는 통치하는 백성의 정착된 성계에서 그 성계에 속하는 프로젝트 행마다 하나(행 이름 사전순 — `StartBlockOf`가 None이면 켜지고, 행의 칸·같은 대응·다른 대응·같은 건설이 막으면 회색 단추에 이름 뒤의 짧은 사유 '(칸 2부터)'·'(답하는 중)'·'(다른 대응 중)'·'(짓는 중)'과 사유가 맨 앞인 툴팁. 그 성계에 서지 않은 위기의 대응과 정착 행에는 단추가 없다 — 아래 '셋째 칸의 ×25와 명령의 사유')와, 통치하는 백성의 것이 아닌 살아 있는 아는 성계마다 정착 단추 하나다(`SettleBlockOf`가 거절하면 회색 단추 + 사유가 맨 앞인 툴팁 + 아래 한 줄, §5.12). 명령 단추의 툴팁에는 사유 다음에 값 한 줄이 선다(아래) — 눌림은 컨트롤러(`StartProject`)를 거쳐 `UPlayerRoleSubsystem::StartMegaproject`로 가고, 컨트롤러는 HUD와 지도를 바로 다시 그린다(멈춘 시뮬은 틱을 보내지 않는다). 프로토타입 키 P는 이 단추로 대신하고 뺐다. 그릇이 육신을 가진 통치자가 아니면 단추가 없다(방랑자의 패널은 Phase 4). 단추 목록은 행동의 목록이 바뀔 때만 다시 짓고, 그렇지 않으면 단추마다 제자리에서 이름·켜짐·툴팁을 고친다(툴팁은 문구가 바뀔 때만 — `SetToolTipText`는 새 Slate 툴팁 객체를 만들어 열린 것을 닫는다): 클릭은 누름과 뗌에 걸쳐 있어서 그 사이에 단추를 다시 지으면 클릭이 버려지고, 시뮬은 1초에 스물다섯 번까지(셋째 칸의 ×25) 틱한다(v0.8의 단계 0에서 고친 버그 — 그 전에는 틱마다 다시 지었다). 꺼진 단추는 코드의 `Press`도 받지 않는다. 꺼진 단추(회색 명령 단추와 상단 바의 지금 배속 단추)는 거의 검은 면 위의 흰 글이다 — Slate가 꺼진 위젯을 면과 글 모두 45% 불투명도로 그려, 기본의 밝은 면 위 어두운 글은 거의 읽히지 않았다(12번 작업의 작은 보완 `UCosmicActionButton`. 리뷰가 면을 더 어둡게, 글을 희게 해 창 없이 찍은 화면의 대비가 약 2.6:1에서 약 3.7~4.2:1이 되었다 — 45% 불투명도가 막는 위는 약 4:1이다. 받아들일지는 손 확인에서). 아키타입 이름은 보이지 않는다(백성의 이름 `CivName`만 — §16 #40 ④를 기본값대로 닫았다: `FCivArchetypeDef.DisplayName`은 개발자용 라벨이다). 단추는 키보드 포커스를 받지 않는다(눌린 단추가 포커스를 쥐면 Space가 정지 대신 그 단추를 누른다). 패널의 상자를 누른 것은 지도의 클릭이 아니다(위젯이 그 누름을 처리한다 — 처리되지 않은 누름은 뷰포트로 올라간다). 로그 피드(4번 작업) `UCosmicLogFeedWidget`: 왼쪽 아래의 `UListView`(가상화), 말해진 항목만(§8.1), 마지막 500줄(§9.4 — 넘치면 가장 오래된 줄이 빠진다), "[주기] 문장", Severity 색(0 회색·1 흰색·2 금색, 초월자의 1인칭 `Log.Transcendent`과 주장 `Log.Claim`은 보라 — §8.2의 넷), 끝을 보고 있었으면 새 줄을 따라간다. 줄을 누르면 그 줄의 성계를 — 없으면 그 줄의 백성의 수도를 — 고르고 카메라가 간다(아는 성계일 때만, §8.1 — 별을 더블 클릭한 것과 같다, 컨트롤러의 `SelectAndFocus`가 모르는 곳을 거절한다). 에디터 바이너리의 리스트 뷰는 블루프린트 항목 클래스만 받으므로(`UListViewBase`, WITH_EDITOR) 빈 위젯 블루프린트 `/Game/CA/UI/WBP_LogEntry`(부모 C++ `UCosmicLogEntryWidget`)를 `Tools/make_widget_blueprints.py`가 만든다(트리는 C++이 짓는다). Phase 1 텍스트 패널은 지웠다. 승천 연출(5번 작업, §6.5) `UCosmicAscensionOverlayWidget`: `UAscensionSubsystem::OnTierAscended`(플레이어의 승천)를 듣고 화면 전체에 약 5초(실제 시간 — 0.8초에 밝아지고 4.2초부터 어두워진다) 보인 뒤 닫히고, 누르면 바로 닫힌다. 보이는 동안 움직이던 시뮬을 멈추고(컨트롤러의 `SetSpeed(0)` — 핸들러는 `SetTimeScale`을 부를 수 있다, §9.4) 닫힐 때 그 배속을 돌려준다. 그 사이 플레이어가 배속을 바꿨으면 그대로 둔다. 보이는 동안의 둘째 승천은 글을 바꾸고 5초를 다시 센다. 셋째 칸의 연출이 닫히면 같은 오버레이가 둘째 단계로 "이제 보인다."를 약 3초 보인다(§6.4 영적 시야 토글 — 막·빛무리·종소리 없음, 누름을 받지 않는다, 그려질 보기가 영적일 때만). 개발용 콘솔 명령 `CosmicPreviewAscension <초>`는 그만큼 뒤에 둘째 칸의 연출을, `CosmicPreviewRung <초> <칸>`은 그 칸의 연출을 보인다(창 없이 찍는 화면에 쓴다 — 둘을 기본 인자 하나로 묶지 않는다: Exec의 기본 인자는 에디터 바이너리에서만 채워지고 게임 바이너리는 인자를 뺀 호출을 거절한다, CLAUDE.md 엔진 표).
**은하 패널**(Phase 3 8번 작업): 선택한 성계가 없을 때 성계 정보 패널의 자리(오른쪽 위, 같은 크기)에 그 은하 — 지금은 고향 은하 — 의 패널 `UCosmicGalaxyPanelWidget`이 선다(시작할 때, 빈 곳이나 배경 점을 누른 뒤, 새 은하와 로드 뒤 — 오른쪽은 언제나 보는 것을 말한다: 성계 하나, 또는 그 은하). 둘은 함께 서지 않는다(별의 수 라벨과 '백성' 줄은 같은 패널에 서지 않는다, §8.3). 줄은 §5.11 '은하 패널'. 그 아래 회색 한 줄 "별을 누르면 그 성계를 본다."(`Galaxy.Hint`)가 보는 사람의 첫 선택까지 선다(위기 포커스가 저절로 고른 것은 세지 않는다 — MVP ⑥의 첫 안내 셋 가운데 하나; 저장하지 않는다 — 별 하나뿐인 첫 5:30에 오른쪽이 사실로 차서 누를 별을 알리지 않게, §16 #106). 마우스만으로 닿는다(새 단추가 없다).
**성역의 패널**(성역은 태양계 `sol` — 다시 쓸 수 없는 법 하나로 소유·정착·주장·파괴에서 빠지는 곳이다, §4.5 ①). **시계 토글**(v0.8 단계 2, 2026-10-18 — WORKPLAN §3 Phase 3 표 11번): 상단 바 시계를 눌러 '주기 1,204'↔'1,204년'(툴팁 "첫 기록부터 센 해 · 1주기 = 1년" 아래 "누르면 주기와 해가 바뀐다." — 납작한 단추라 누를 수 있음을 툴팁이 알린다), 마우스를 올리면 두 단위를 함께 '주기 1,204 · 1,204년(첫 기록부터)'(띠의 너비가 모자라면 상단 바의 연구 덩이가 줄어 '…'로 끝난다 — 셋째 칸의 년 단위에서 시계에 마우스를 올리면 그렇다. 연구 덩이는 시계를 덮지 않는다, 12번 작업의 리뷰). 피드 머리와 패널 카운트다운('120년 남음')도 따르고, 년 모드의 배속 단추는 '1년/초 … 10년/초'(셋째 칸부터 '25년/초'). 보는 사람의 설정이라 상태·해시 밖이다. 기본은 '주기'다(§16 #82). 단위는 플레이어 컨트롤러의 표현 상태(`ECosmicTimeUnit`)이고 보는 사람의 `GameUserSettings` ini에 남는다 — 자동화 테스트가 도는 동안에는 쓰지 않고, 테스트는 단위를 메모리에서 정해 개발자의 설정을 답으로 읽지 않는다. 라벨 함수는 단위를 인자로 받는다(`CosmicUI::ClockLabel`·`TimeLeftLabel`·`StampLabel`·`SpeedLabel`).
**셋째 칸의 ×25와 명령의 사유**(v0.8 단계 3의 몫, Phase 3 12번 작업, 2026-10-18 — 직접 승인한 헤더 초안과 그 수정 `Saved/Design/phase3_reasons/header_draft.md`):
**×25 단추**: 시뮬은 배속을 0..`MaxTimeScale`(25)로 자르기만 한다(0 이하이거나 숫자가 아니면 정지. 프레임당 10틱·이월 10틱은 그대로라 2.5fps 위에서 초당 25틱이다, §9.4). 어느 배속이 열리는가는 표현 계층의 규칙이다(`CosmicUI::SpeedSteps`·`IsSpeedOpen`·`OpenSpeed` — 핵심 로직은 플레이어의 것을 갖지 않는다): ×10까지는 늘, ×25는 셋째 칸의 문이 열릴 때(영적 시야의 문 `CosmicMapLook::SpiritualSightOpens` — 개발용 강제 `CosmicSpiritualSight 1`도 연다). 단추는 셋째 칸에 오르는 틱의 승천 연출이 닫힐 때 나타난다(연출이 보이는 동안은 접혀 있다 — "이제 보인다."와 같은 때. 연출의 `Close`는 언제나 HUD를 다시 그린다). 툴팁은 숫자 키 다음 줄에 "셋째 칸에서 열리는 배속이다 — 위기의 남은 시간도 그만큼 빨리 지나간다.". 열리지 않은 배속은 어느 길로도 서지 않는다 — 단추·정지 풀기(`SpeedBeforePause`)·연출이 돌려주는 배속은 컨트롤러의 `SetSpeed`를 거쳐 ×10이 되고(컨트롤러 없는 상단 바도 같은 규칙으로 시뮬에 준다), 열리지 않은 단의 키는 아무것도 하지 않는다(§2.1). 키는 문만 따른다 — 연출이 보이는 동안에도 키 5는 ×25다(키 1~4가 연출 아래에서 제 배속을 정하는 것처럼. 상단 바의 ×25 단추만 연출이 닫히기를 기다린다). 돌던 ×25는 문이 닫히는 틱(폐위·새 은하·더 낮은 세이브의 로드)에 ×10으로 내려온다(컨트롤러의 `FollowSpeedGate` — `OnSimTick`·`OnGalaxyGenerated`에서. 처음 보는 문은 적기만 하므로 문이 연 적 없는 개발용 `-Speed=25`는 그대로다).
**명령의 사유**: 위 단추 문장과 §5.7의 `StartBlockOf`. 회색 사유는 넷이다 — 행의 칸('칸 N부터 시작할 수 있다.' — N은 행의 `RequiredTier` + 1, 상단 바처럼 1~5), 같은 대응('이미 이 위기에 답하고 있다.'), 다른 대응('대응 칸에서 이미 다른 대응을 하고 있다 — 대응은 한 번에 하나씩이다.'), 같은 건설('이미 건설 칸에서 짓고 있다.'). 시작한 행은 사라지지 않고 회색 '(짓는 중)'으로 남아 단추가 커서 밑에서 움직이지 않는다. 비용은 회색이 아니다 — 모든 명령 단추(정착 단추 포함. 다른 백성이 사는 곳과 정착 행이 없는 곳은 빼고)의 툴팁에 값 한 줄 '주기마다 에너지 2 · 물질 1 — 값을 다 낸 주기에만 나아간다.'(년 단위면 '해마다 … 해에만'. 값이 없으면 '값이 들지 않는다.' 수는 멤버마다 정수면 정수, 아니면 소수 둘째 자리까지 — 끝의 0 없이 '에너지 1.5 · 물질 1'), 값이 드는 건설 행에는 '위기에 답하는 일이 먼저 값을 낸다 — 답이 값을 기다리는 동안 건설은 멈출 수 있다.', 건설 칸에 다른 행이 돌면 '시작하면 건설 칸에서 짓던 {이름}의 진척이 사라진다.'가 붙는다(이 줄은 사유 바로 다음, 값 줄보다 먼저 선다 — 되돌릴 수 없는 잃음이다, 12번 작업의 리뷰. 문구는 비축을 읽지 않아 틱이 지나도 툴팁 객체가 그대로다). 회색으로 막지 않는 까닭: 값을 못 내는 채로 시작한 대응은 쓸모 있는 명령이고(§5.7의 기다림 규칙 — 그 백성의 건설보다 먼저 값을 받는다), 명령·AI·단추는 한 답을 읽는다(규칙 하나). 패널에만 둔 회색은 그 규칙을 가르고 첫 생애의 첫 단추를 처음 두 주기 동안 흐리게 하며, `CanStart`에 넣은 비용은 AI의 세계와 두 해시를 바꾼다. v0.8 17.7이 회색 사유로 든 '비용'은 이 값 한 줄로 읽었다(§16 #101 — 개발자에게 묻는다).
**'멈춤 — 자원 부족'**: 통치하는 백성의 칸에만 단다(다른 백성의 칸에 달면 그 비축을 알린다). 세계는 낸 틱을 적지 않으므로 패널이 이어진 두 틱의 칸을 견준다(`CosmicMegaprojects::ReadSlot`·`PaidNothing` — 같은 행이 정확히 같은 진척이면 그 틱에 내지 못했다: 낸 틱은 진척을 더하거나 완성해 칸을 비우고, 값을 기다리는 답 때문에 멈춘 건설도 자원이 모자란 것이라 같은 말이다). 깜박이지 않게 두 틱 연속으로 못 내면 달고 두 틱 연속으로 내면 뗀다(`CosmicSlotWatch` — 첫 생애의 다이슨 스웜은 수입 1에 값 2라 한 주기 걸러 내므로 한 틱 규칙은 첫 분부터 깜박였다). 그래서 절반을 내는 첫 생애의 스웜에는 표시가 없고, 셋에 하나를 내는 칸에는 진척이 오르는 동안에도 '멈춤'이 선다(§16 #103). 패널의 표현 기억이다: 성계 ID마다, 통치하는 백성의 모든 성계(정착 중 포함)의 두 칸을 보고(새로 고른 성계도 바로 안다), 핵심 로직의 방송 안에서는 판정하지 않으며(틱 도중에는 아직 내지 않은 칸이 있다), 새 은하와 로드에 비운다. 성계가 통치하는 백성의 것이 아니게 되거나(넘김) 그릇이 통치자가 아니게 되면(폐위) 그 칸들은 더 보지 않고, 칸 줄은 표를 달기 전에 주인을 스스로 묻는다(방송 안의 다시 그리기는 칸을 보지 않으므로 — 12번 작업의 리뷰). 저장·해시 밖.
**'다음 칸까지'**: 상단 바의 이름·칸 덩이의 툴팁이다 — 연구 넷 덩이의 툴팁(`GetResearchTip`, 아래 '연구 중점')은 중점 한 줄과 빈 줄 뒤에 이 글을 붙인다(덩이마다 제 함수에 한 번 묶여 마우스가 올라 있을 때만 글을 만든다 — `ToolTipTextDelegate`. `SetToolTipText`는 부르지 않는다: 바뀔 때마다 새 툴팁을 만들어 열린 것을 닫는다). 이름·칸은 마우스를 올리면 시계처럼 금빛이 된다(보일 툴팁이 있을 때만 — 다음 칸이 없으면 흰 그대로, 12번 작업의 리뷰). 글은 업적 판정을 그대로 따라 읽는 순수 함수 `CosmicNextRung::Of`·`TextOf`가 만든다: 그릇이 육신을 가진 통치자이고 그 백성에 정착된 성계가 있을 때, 그 칸에서 오르는 첫 통치자 업적 행(판정·AI의 선택과 같은 거르개 `FAscensionFeatDef::IsJudgedRulerRowAt`)의 조건마다 판정의 평가기(`UCosmicEventSubsystem::Check`, 그릇의 출생 틱부터 — 출생 전의 완성은 세지 않는다)로, 판정이 한 성계에서 모두를 요구하므로 가장 많이 서는 정착된 성계 하나에서 읽는다. 프로젝트는 '이름(완성)'·'이름(진척/필요)'·'이름(<위기>에 답할 때)'·'이름(시작 전)', 연구는 '물리 50%(34%)'(지금 몫은 상단 바와 같은 반올림이되 못 미친 몫은 필요한 몫보다 1% 아래까지만 — 0.496은 50%가 아니라 49%), 그 밖의 조건은 숫자 없이 하나로 '그 밖의 조건(갖춤)'·'(아직)'. 셋째 칸(VS에는 그 위의 행이 없다)·다섯째 칸·방랑자·공백기에는 이름·칸 덩이의 툴팁이 없다(연구 덩이는 다스리는 백성이 있는 동안 중점 한 줄을 남긴다). 한 칸에 행이 여럿이면(EA) 첫 행만 보인다(§16 #104).
**자동 일시정지**(MVP ①, 2026-10-20 — 표현 계층만, 상태·해시·추첨 밖): 달리는 시뮬을 화면이 스스로 멈추는 경우는 셋이다 — ① 말해진(`OnLogEntry`가 알린) Severity 2 줄(`bUntold` 줄은 알리지 않으니 멈추지 않는다; 먼 줄·만남·돌파·위기의 줄은 Severity 0~1이라 멈추지 않는다), ② 통치하는 백성이 가진 성계에 위기가 새로 서는 것(위기의 줄은 Severity 1이라 따로 본다 — 컨트롤러가 틱 경계(`OnSimTick`)마다 그 백성의 성계와 위기를 지난번과 견준다: 새 위기나 다른 위기면 멈추고, 같은 위기가 서 있거나 끝나면 아무 일도 없다. 새 은하와 로드 뒤의 첫 봄은 적기만 한다), ③ 카드의 도착(MVP ② — 컨트롤러가 틱 경계(`OnSimTick`)마다 대기 카드를 보고(`FollowPetition`) 새 카드면 `RequestAutoPause(Card)`를 부른다. 새 은하와 로드 뒤에 기다리는 카드는 멈추지 않고 뜬다. 카드의 결과를 닫으면, 카드가 멈춘 채 아무도 배속을 정하지 않았을 때만 멈추기 전 배속을 돌려준다 — 사슬의 다음 카드는 멈춘 채 뜬다). 멈춤은 배속 단추와 같은 길(`ACosmicPlayerController`의 `SetSpeed(0)` — 돌아갈 배속을 기억해 Space가 이어간다)이고, 이미 멈춘 시뮬과 끔 상태에는 아무 일도 하지 않는다. 틱 단계 안의 처리기에서 부르는 것은 `SetTimeScale`뿐이라 규칙 5 안이다(남은 틱은 그 프레임에 돌지 않는다). 보는 사람의 설정이다: 기본 켬, 상단 바의 배속 단추 뒤 단추 '자동 정지 켬/끔'(툴팁이 멈추는 세 경우를 말한다)으로 끄고 켜며, 그 선택은 시계 단위처럼 `GGameUserSettingsIni`의 `Cosmic_Ascension.View`·`AutoPause`에 남는다(자동화 테스트는 쓰지 않는다. 개발용 `-AutoPause=0`·`1`은 그 세션만 — 프레임 시간 측정). 자동으로 멈춘 동안 단추 곁에 까닭 한 줄('정지 — 큰 일이 기록되었다'·'정지 — 다스리는 성계에 위기가 섰다'·'정지 — 청원이 왔다', 금빛)이 서고, 배속이 다시 정해지면(단추·숫자 키·Space·승천 연출이 돌려주는 배속) 사라진다. 새 은하와 로드도 까닭을 지운다. 승천 연출과의 순서: 승천의 줄(Severity 2)이 `OnTierAscended`보다 먼저 와서 시뮬을 멈추므로, 켬이면 연출은 멈춘 시뮬을 받아 닫힐 때 배속을 돌려주지 않고(멈춘 채 까닭이 남는다), 끔이면 지금처럼 연출이 멈췄다가 돌려준다. 헤드리스 도약(`RunHeadless`)과 커맨드렛은 알림 문이 닫혀 있어 멈추지 않는다. 테스트 `UI.AutoPause`(`Sim.FrameStep`의 프레임 실행은 이 장치를 끄고 잰다). **위기 포커스**(MVP ⑥, 2026-10-24): 다스리는 백성의 성계에 새 위기가 서서 이 장치가 시간을 실제로 멈출 때(`RequestAutoPause`가 참을 돌려준다), 컨트롤러가 그 성계를 고르고 카메라를 보낸다(`CosmicAutoPause::FirstNewHazardSystem` — 한 번에 둘이면 배열 차례의 첫째; 팔 3,000 이내로, 우주 화면에서는 구역으로 돌아온다; 패널이 위기와 남은 주기를 보인다). 자동 정지 단추의 툴팁(`AutoPause.Tip`)이 이 포커스를 말한다. 끔이거나 이미 멈춘 판에서는 움직이지 않는다 — 멈춤 하나에 움직임 하나. 저절로 고른 것은 보는 사람의 고름이 아니라 안내의 기록(`bPickedSystem`·`bLeftUniverse`)을 쓰지 않고(`SelectAndFocus(…, false)`), 누르는 중이던 마우스의 뗌은 클릭이 되지 않는다. 같은 경계의 카드는 위기 다음이라(틱 경계의 차례 `FollowOwnHazards` → `FollowPetition`) 시간을 멈춘 것은 위기이고 카메라는 카드 뒤에서 다가간다. 위기의 끝과 해결은 저절로 움직이지 않는다(피드의 줄을 누르면 간다).

접히고 대기 행은 앎에 남는다(다시 오르지 않는다). 시계 끝에서는 6,000번째 틱이 열 단계를 다 돈 뒤 그 틱의 경계가 래치를 걸고, 프레임 고리가 걸음마다 배속을 다시 보므로 6,001은 돌지 않는다. **칸 끝의 두 순서**: 자동 정지가 켜져 있으면 승천 줄이 먼저 멈추고(연출은 0을 쥔다) 그 틱의 경계에서 래치가 까닭을 `RunEnd`로 바꾼다. 꺼져 있으면 연출이 배속을 쥐고 멈춘 뒤 래치가 서고, 연출을 닫을 때의 되돌림은 문에 걸려 0이다. 연출과 '이제 보인다'의 드러냄이 끝난 뒤 멈춘 지도를 1.5초(실제 초) 보이고 연대기 화면 `UCosmicChronicleWidget`(HUD Z 20, WBP 없는 C++ 위젯)이 열린다 — 막이 1초에 어두워지고 줄이 0.25초 간격으로(쪽 전체 6초 안) 드러나며, 한 번 누르면 다 드러난다. 쪽은 `docs/70` §8.4의 최소형이고, 스크롤 밖 아래에 까닭 줄('6,000주기가 흘렀다 — 이 판은 여기까지다.' 또는 '<백성>이 셋째 칸에 이르렀다 — …')과 시험판 알림, 다 드러난 뒤에만 서는 단추 둘이 있다 — '지도 보기'(쪽이 접히고 시간은 멈춘 채다. 카메라·선택·패널·피드·시야 토글은 된다)와 '새 판'(3초 안에 두 번 누르면 시계 시드로 새 은하를 열고 ×1 — `-Seed=`는 첫 판만이다. 끝난 판은 저장에 남고 다음 시작의 이어하기가 끝난 채 연다 — 새 판을 열면 그 뒤로는 새 판을 잇는다, MVP ⑤). 끝난 판에서는 상단 바의 배속 단추가 모두 회색이고(셋째 칸이면 ×25도 서되 회색), '이 판은 주기 6,000에 멈춘다.'(폐위는 끝이 아니다 — 2026-10-18 결정). 끝난 판으로 서는 게임(로드·두 `BeginPlay`)은 기다림 없이 다 드러난 쪽으로 열고 카드를 올리지 않는다. 래치가 설 때 로그에 한 줄 `CosmicEnd: <Rung|Clock> at tick <틱>; <초> s since tick <틱>, <초> s of `-ProvisionalEnd=0`(그 세션 동안 끝을 끈다 — 6,000틱 너머의 화면과 손 시험), `CosmicPreviewChronicle <초>`(끝내지 않고 지금 상태의 쪽을 다 드러난 채 연다 — 까닭·알림·'새 판' 없음). 래치는 컨트롤러 멤버라 테스트를 넘어 남으므로 `CosmicTests::AcquireSim`이 지우고 스위치를 켠다. 테스트 `UI.RunEnd`·`UI.Chronicle`(`UI.MouseOnlyAscent`가 칸 끝의 마우스 길을 본다). **서막과 부르심의 화면**(v0.8 — 단계 6부터): 서막은 표현 계층의 상태다 — 저장하지 않고, 시뮬은 `SetTimeScale(0)`(일시정지 규칙 그대로)이며 배속 입력이 없다. 카드는 Phase 4의 조우 카드 화면을 먼저 만들어 쓴다. 부르심에는 승천 오버레이를 쓰지 않는다 — 카메라가 출생 성계에서 넓은 하늘로 물러나고 상단 바·피드·패널이 켜진 뒤 ×1이다. 서막의 결과는 부르심의 Core 함수(가칭 `ReceiveCalling`, §7.5)가 상태에 적는다(§4.4). 서막의 성계 화면과 물러나는 카메라는 줌 단계 '성계'(구역 아래의 열거자와 멈춤 한 쌍)로 §6.4 '우주 화면'의 줌 단계에 더한다.

카메라: 스프링 암을 가진 폰 `ACosmicCameraPawn`(Phase 3 2번 작업 — 게임 모드가 만들어 조종한다. `L_Galaxy`에 PlayerStart가 없어 기본 폰으로 두지 않는다). 오른쪽 드래그로 궤도 회전(위아래 −85°~−20°), 휠로 줌(한 칸 ×0.85 — 구역은 1,500부터 원반 반지름의 3배까지, 그 너머 한 칸이 우주 화면의 가까운 끝, 아래 '우주 화면'), 왼쪽 드래그로 이동(지난 프레임에 커서 밑에 있던 원반의 점이 지금 커서 밑에 오도록 — 6픽셀 넘게 움직인 누름은 클릭이 아니다), 별을 더블 클릭하면 그 별로 다가간다(거리 3,000). 조작은 목표값을 정하고 폰이 실제 시간으로 그쪽에 미끄러진다(시뮬의 정지와 무관 — 이동만 바로 옮긴다). 새 은하와 로드는 원반 전체를 보는 시점으로 바로 간다(맵 액터의 `OnRebuilt`). 클릭은 라인 트레이스가 아니라 화면 공간에서 고른다: 커서에서 24픽셀 또는 그 별이 화면에 그려진 반지름 안에 있는 별 가운데 가장 가까운 것(`CosmicMapPick::NearestOnScreen` — 개관 거리에서 별은 약 10픽셀이라 구에 대는 트레이스는 정확히 찍어야 했다. 별의 충돌은 껐다). 빈 곳을 누르면 선택이 풀린다. 선택은 표현 상태다: 플레이어 컨트롤러가 들고(`SelectSystem`·`OnSelectionChanged` — 3번 작업의 정보 패널이 듣는다) `FGalaxyState` 밖이라 저장·해시와 무관하며, 지도는 선택한 별을 주인 고리 바깥의 흰 고리로 보인다. 멀리서(카메라 거리 9,000 초과)는 주인이 있거나 위기가 선 성계와 선택한 성계의 이름표만 보인다(`CosmicMapLook::ShowsLabel`). 개발용 콘솔 명령 `CosmicSelect <성계ID>`는 더블 클릭처럼 고르고 다가간다(창 없이 찍는 화면에 쓴다). 줌 단계는 성계(서막)·구역·은하·우주다(v0.8 — 우주는 Phase 3 9번 작업, 성계(서막)는 단계 6부터. 지금은 휠 줌 하나다). 실제 하늘(단계 5) 뒤 지도는 태양 중심 방위 등거리 투영이다 — 방향 = 은하 경도, 태양까지의 거리 = 실제 3D 거리. 좌표와 레인(교차 없는 평면 그래프, 차수 ≤ 4, 손 고침 파일, 태양을 빼도 이어진다)은 오프라인 도구가 미리 계산하므로 C++에 삼각 함수가 없다(§9.2). 실제 하늘 뒤에는 행성이 알려지지 않은 유명한 별(시리우스·프로키온·알타이르·베가·포말하우트 등)을 고를 수 없는 배경 점으로 두고, 태양 둘레에 10·20·30광년 금을 숫자 없이 그린다 — 출처가 깨끗한 공개 목록에서 오고, 표현 계층만이라 해시 밖이다(v0.8 — 단계 5부터).

움직인다(미끄러지는 중에 끌어도 튀지 않는다). 카메라·단계·은하 선택·안내 진척은 표현 상태다(저장·해시 밖, 새 은하와 로드는 구역에서 선택 없이). 그릴 값은 순수 함수 `CosmicUniverseLook`이 준다: 단위는 고향 은하 반지름 하나(단계 5 전에는 지도의 원반이 곧 고향 은하다 — 원반 반지름), 이름 있는 은하는 자리가 있는 찍은 화면을 보고 0.6에서 낮췄다 — 가장 밝은 화소의 채도 약 0.13~0.15, 더하는 블렌드라 겹친 곳은 더 희다), 색은 먼지의 옅은 푸른빛 하나 — 어느 은하도 특별하지 않다(가장 크지도 가장 밝지도 않은 M87, 보좌로 읽힐 그림이 없다). 풍경 은하는 `DeriveForName(0, HomeGalaxyRow, Scenery, 0)`의 지역 `SceneryGalaxyCount`, 빛 0.04~0.2로 이름 있는 은하보다 언제나 어둡다). 행은 추첨을 움직이지 않는다: 이름 있는 은하 밑의 점은 어둡게만 한다. 먼 끝 화면의 네 모서리는 풍경 안이라 쉬는 화면에 테두리가 없다. 거리에 따라: 두 단계 사이의 몫 u(구역의 먼 끝 0, 우주의 가까운 끝 1)로 먼지는 1 − u, 우주는 u만큼 보이고(`M_Backdrop`의 `LayerFade` — 다시 그리기 없음, u가 0이면 우주 메시를, 1이면 먼지를 숨긴다), u가 절반을 넘으면 구역의 상세(성계 액터·이름표·레인·고리)를 그리지 않는다(넘을 때 다시 그리기 한 번 — 우주 단계의 다시 그리기는 은하 이름표와 고리만). 이름표는 이름만이다(수치는 은하 패널에, §8.3) — 고향의 이름표는 늘, 다른 은하는 보는 거리의 5.5% 이상 크거나 골랐을 때. 클릭은 그려진 것만 고른다: 구역에서는 별, 우주에서는 이름 있는 은하(풍경은 빈 자리), 은하를 더블 클릭하면 그 은하로 다가가고(그 반지름의 3.5배, 가까운 끝보다 가깝지 않게), 고향을 더블 클릭하면 구역 전체로 돌아온다. 두 선택(성계·은하)은 저마다 제 단계에 살고, 오른쪽은 단계가 정한다(`PanelOf` — 구역은 고른 성계의 패널이나 고향의 은하 패널, 우주는 고른 은하나 고향의 은하 패널. 두 패널은 함께 서지 않는다). 안내는 은하 패널의 회색 한 줄, 세션에서 한 번씩: 별을 누르라 → 휠로 더 멀리 → 은하를 누르라 → 고향을 두 번 누르라('{Home}을 두 번 누르면 별들이 다시 보인다.'). 우주 화면에는 수가 없다(축척·광년 고리·은하 수 없음 — 단계 5의 것), 다리를 그리지 않는다(갈 수 없는 길을 그리지 않는다), 영적 시야는 우주에서 아무것도 하지 않는다(보기 단추가 무엇도 바꾸지 않는다 — 타락은 건너지 않는다. 하늘과 우주의 `SpiritualIntensity`는 그 값 × (1 − u)). 하늘은 우주를 담도록 다시 짓기마다 크기가 바뀌고 성운 노이즈는 보는 방향으로 읽는다(무한히 먼 하늘). 6a의 요약 낱말은 은하 패널의 글로만 — 우주 화면의 색·고리·표지가 되지 않는다. 개발용 `CosmicWheel <칸>`(양수 다가감)·`CosmicSelectGalaxy <행>`.
성계 상태 표시(Phase 3 1번 작업에서 정했다): 항성 등급의 색·크기와 Hazard 경고(별 전체의 맥동)는 `M_Star`의 파라미터, 소유 문명 색은 별을 두르는 선의 고리(정착 중이면 끊긴 고리 — 구 위의 테두리는 개관 거리에서 몇 픽셀이라 읽히지 않았다), 이름과 건설·대응 칸의 진척은 성계마다 작은 화면 공간 위젯(`UCosmicSystemLabelWidget`)이다. 지도는 맵 액터 `ACosmicGalaxyMapActor` 하나가 그린다: `ACosmicGameMode::StartPlay`가 만들고(`L_Galaxy`는 고치지 않는다), `OnGalaxyGenerated`(새 은하와 로드)에 성계 액터를 다시 짓고, `OnSimTick`에는 표시만 해 두어 다시 그리기는 프레임마다 많아야 한 번이다(10배속에서도 그리는 비용이 틱 수를 따라 늘지 않는다). 그릴 값은 상태만 읽는 순수 함수 `CosmicMapLook::LookOf`·`LanesOf`가 계산한다(테스트 `UI.GalaxyMap`이 그리지 않고 본다). 선의 두께는 월드 단위라 카메라 거리에 비례하게 다시 잡는다(2번 작업 — 화면에서 약 1.2픽셀. 고정 두께는 멀리서 점선으로 끊기고 가까이서 13픽셀이 되었다. 거리가 5% 넘게 바뀌거나 먼 시점의 경계를 넘을 때만 다시 그린다). 머티리얼 `M_Star`·`M_Nebula`는 `Tools/make_materials.py`가 만든다(데이터 테이블처럼 생성물이다 — 에디터에서 고치면 덮어써진다. 성계 액터와 맵 액터는 생성자의 `FObjectFinder`가 아니라 `BeginPlay`의 `LoadObject`로 읽는다: 생성자 탐색은 머티리얼을 프로세스 내내 루트에 묶어 스크립트가 제자리에서 다시 채우지 못한다. 쿠킹은 `DirectoriesToAlwaysCook`의 `/Game/CA/Materials`). 앎의 표시(아래, 8번 작업)는 그 뒤에 문 하나로 걸린다 — 지도가 그리는 모습은 세계의 모습(`LookOf`)을 아는 것으로 거른 모습(`ShownLookOf`)이다. 성역의 그림(v0.8 — 단계 4부터): 주인 고리 없음, 색 없음, 이름표 '태양계 · 성역'. 셋째 칸의 영적 시야(아래 '영적 시야 토글', 7번 작업)는 같은 별·선·하늘을 다르게 그린다 — 별의 영적 파라미터, 반쪽 레인, 봉인 고리, 하늘의 `SpiritualIntensity`.

**앎의 표시**(Phase 3 8번 작업, 2026-10-18 — 승인한 헤더 초안과 그 수정 `Saved/Design/phase3_known/header_draft.md`, 다르게 간 곳은 그 끝의 'As built'): 표현 계층은 `FGalaxyState.Knowing`(아는 성계·만난 백성·만난 은하 — §7.2, §8.1)을 읽어 무엇을 그릴지 가른다. 표시일 뿐이라 저장·해시와 무관하다(Phase 3 꼬리, §11).

- **한 번 읽기**: 표현 계층이 앎을 읽는 곳은 `CosmicMapLook::KnownViewOf` 하나다 — 지도와 패널의 다시 그리기마다 한 번 읽어 배열 번호로 된 값(`FCosmicKnownView` — 성계마다 아는가 한 비트, 백성마다 보일 때의 만난 순서)을 내고, 지도·성계 패널·선택·클릭·피드의 누름이 그 답(`IsKnown`·`IsShownByName`·`IsShown`·`ShownOrderOf`·`OwnerShownOf`)을 읽는다. 앎에는 쓰지 않는다(§8.1 ②). 은하 패널은 정의(`DT_Galaxies`·ST_CA)만 읽는다 — 만난 은하(Phase 6a)가 오면 그 비트를 뷰에 더한다. 성역도 이 뷰로 들어온다(A0 4a) — 이름만 보이는 둘째 비트 `ShownByName`(`KnownViewOf`가 성역의 ID로 세운다)이 있고, 그리기·고르기·선택의 문은 `IsShown`(= `IsKnown` ∨ `IsShownByName`)이다: 모습(`ShownLookOf` — 이름과 별만)·슬롯(`LightSlots`)·레인(`KnownLanesOf`)·클릭(`PickCandidatesOf`)·선택(`SelectSystem`)·성계 패널의 앎 문(`Refresh`). 주인을 알리는 답(`OwnerShownOf`)은 `IsKnown`만 읽는다. 성역에는 레인이 없다(A0 결정 2 — 단계 5가 실제 하늘의 레인을 정한다).
- **보이는 백성** = 만났고 보는 쪽보다 세 칸 이상 위가 아닌 백성 — 이야기의 범위의 주제 규칙 그대로다(`CosmicMapLook::IsShownPeople`, 보는 쪽 Tier는 `GetViewerTier` — 통치하는 동안은 통치하는 백성의 칸). 같은 격차 규칙이 `UCosmicLogSubsystem::Tell`·`NoteMet`·`IsShownPeople` 세 곳에 있어 테스트가 묶는다(`UI.KnownFilter`의 대조 — 지도가 한 백성을 보이는 것과 그 백성의 줄이 말해지는 것이 같다. Phase 4가 범위를 고칠 때 Core의 술어 하나로 옮긴다, §16 #107). VS의 게임에서 세 칸 위의 만난 백성은 나오지 않는다(T3→T4 행이 없다) — EA와 공백기(4b)의 경우다.
- **모르는 성계는 배경 별의 점 하나다**: 별(구)을 숨기고(이름표도), 배경 별 인스턴스가 그 성계의 자리에 둔 슬롯 하나를 배경 별과 같은 법칙으로 밝힌다(`CosmicMapLook::BackdropSlotOf` — `Derive`의 Backdrop을 그 SystemID로 연 지역 스트림, 같은 메시·머티리얼·크기·밝기·가까이의 흐림, 영적 시야에서 함께 물러남). 그 성계를 알게 되면 다음 다시 그리기에서 슬롯이 어두워지고 별이 선다. 그래서 모르는 성계는 배경 별처럼 '그려지는' 것이 아니라 배경 별 하나**다** — 따로 셀 수 없다(§12.2의 미구현 목록). 이름·이름표·소유 고리(끊긴 고리 포함)·Hazard 맥동·진척 막대·레인·영적 표식·봉인 고리·선택 고리가 없고 고를 수 없다. 파괴된 모르는 성계도 그 점으로 남는다(아무도 보지 않은 파괴는 보이지 않는다). 파괴된 아는 성계는 희미한 죽은 별이다(§7.2). 머티리얼 파라미터 `Known`은 두지 않았다 — 구 위의 값은 구를 흐리게 할 뿐 '같은 점'이 되지 못한다(§16 #105). 새 색을 쓰지 않는다: 희미한 점과 밝은 별이다.
- **아는 성계**는 이름·항성 등급·Hazard·죽음·생명 낱말(§5.7)과 초월자의 표식(칸으로 열린다, §3.2)을 보인다. 소유 고리(만난 순서의 색)·정착 중의 끊긴 고리·이름표의 두 막대·멀리서 소유로 켜지는 이름표·주인의 이름·'{PopBand} 백성'·칸 줄은 주인이 보이는 백성일 때만이다 — 그 백성의 것이라서(`ECosmicOwnerShown`). 보이지 않는 주인의 성계는 패널에 '주인  다른 백성'이라 하고(`Panel.OtherOwner`) 정착 단추는 '이곳에는 이미 다른 백성이 산다.'라 한다 — 백성을 부르지 않고 한 이야기를 한다: 여기 누가 살지만 아직 알아보지 못했다(§16 #108). 그 성계의 Hazard와 영적 표식은 보인다(맥동은 주인의 칸을 읽는다 — 셋째 칸부터만 보이고 그때 VS의 백성은 격차에 가려지지 않는다). VS에서 보이지 않는 주인의 아는 성계는 AI가 아는 성계를 정착하거나 받은 뒤 다음 앎 단계까지(10틱) 선다.
- **만났으나 사라진 백성은 표시에서 빠진다** — 지도와 목록의 말이다: 사라질 때 가진 성계가 없어(건넘 단계는 성계 없는 백성만 지운다) 그릴 것이 없고, 만난 순서의 자리는 지킨다(CivID는 다시 쓰지 않으므로 어떤 색도 다른 백성에게 옮지 않는다). 이야기의 층(피드에 이미 말해진 줄)은 그대로다.
- **레인**은 두 끝이 모두 아는 살아 있는 성계일 때만 그린다(`CosmicMapLook::KnownLanesOf`) — 모르는 끝으로 가는 토막도 없다(먼지에서 가려낼 수 없어야 할 점을 가리키게 된다). 영적 시야의 반쪽 레인도 그린 레인에서만.
- **팔레트**: 문명의 지도 색은 `Knowing.MetCivs`의 순서대로 12색 팔레트에서 준다(`CosmicPalette::Owners`·`OwnerColorOf` — 첫 생애의 백성이 첫 색, 열세 번째로 만난 백성부터는 첫 색에서 다시 돈다. EA 규모에서는 Phase 6a에 다시 본다) — 소유 색이라 Severity 4색 상한과 별개이고, 상태의 `Color`는 그대로 두되 어디에도 그리지 않는다(`LookOf`가 그 색을 싣지 않는다 — §16 #36 ⑥ 닫음). 팔레트의 열두 색은 타락의 색상 띠(약 250°~330° — 보라·자주·자홍)를 비운다: 셋째 칸의 영적 시야에서 보라는 타락의 것뿐이다(그래서 영적 시야의 주인 고리 규칙 `OwnerRingColorOf`는 일부러 남겨 둔 쉬는 지킴이다). 값은 화면의 값이다(지도의 선은 그 수를 그대로 sRGB 바이트로 그린다 — 테스트는 sRGB를 풀어 OKLab으로 잰다) — 쌍마다 0.07 이상, 고정 색(회·백·금·보라, 레인의 파랑, 두 경고, 죽은 별의 회색, 검정)과 0.07 이상, 제1·2형 색각 이상(Machado 2009)에서 첫 생애의 색과 처음 만나는 셋은 0.1 이상, 모든 색과 보라는 0.04 이상. 순서는 셋(정상·제1형·제2형) 가운데 가장 나쁜 쪽에서 가장 먼 점부터다 — 처음 만나는 이웃이 가장 다르다. 열두 색을 모든 눈에 가르는 것은 할 수 없다: 색이 모자란 눈에는 패널의 주인 줄이 백성을 부른다(§16 #109). 띠 바로 밖의 분홍 둘(장미·와인 — 화면에서 색상 약 342°·337°)과 처음 만나는 두 이웃의 어두운 색(코발트·주홍)은 §16 #109에서 화면을 보고 정한다.
- **선택·카메라·클릭**은 아는 성계만 받는다: 컨트롤러의 `SelectSystem`이 모르는 성계를 거절하고(아무것도 바뀌지 않고 알리지 않는다), `SelectAndFocus`는 거절되면 카메라를 옮기지 않으며, 클릭은 아는 별만 고른다(`ACosmicPlayerController::PickCandidatesOf` — 선택과 같은 살아 있는 뷰를 읽는다). 배경 점을 누르는 것은 빈 곳을 누르는 것이다(선택이 풀리고 은하 패널이 돌아온다). 더블 클릭을 끝내는 뗌은 클릭이 아니다(8번 작업의 수정 14 — 2번 작업부터 숨어 있던 결함: 그 뗌이 미끄러지는 시점으로 클릭을 다시 돌려 막 고른 선택을 풀거나 옮길 수 있었다). 보는 사람이 누르지 않고 성계를 골라 카메라를 그리로 보내는 길은 위기 포커스 하나다(MVP ⑥, §6.3 '자동 일시정지' — 같은 문을 지나고, 안내의 기록을 쓰지 않으며, 누르는 중의 뗌을 삼킨다. 새 은하·로드의 다시 짓기와 셋째 칸 연출의 구역 잡기는 성계를 고르지 않는다). 피드의 줄은 그 줄의 성계나 그 백성의 수도가 아는 곳일 때만 간다(§8.1). 말해진 줄은 거르지 않는다 — 이야기의 범위가 이미 만나지 않은 백성을 피드 밖에 둔다.
- **은하 패널**: 선택한 성계가 없으면 성계 패널의 자리에 은하 패널이 선다(§6.3, §5.11 '은하 패널'). 열리지 않은 은하(만난 은하가 아닌 것 — 6a 전에는 모든 은하)는 종류와 현실 수치 문구(§8.3)와 모든 은하에 같은 한 줄 "이 은하의 별들도 하나도 빠짐없이 이름대로 불렸다."뿐이다 — 관할 분류·소속 값 없음(v0.8 — Phase 3 8번 작업).
- **초월자**는 만남의 대상이 아니고 그 뒤에도 호칭만 가진다(§3.2). 첫 접촉 뒤에도 교단 지도자와 초월자는 이름을 얻지 않는다. 영적 시야는 아는 성계에만 표식을 묻는다(모르는 성계는 영의 모습이 비어 맥동·색·주장 표식·봉인 고리가 없다).

'고압 구간 채도 저하'의 정직한 꼴: 영적 시야에서 레인마다 두 끝에서 가운데까지의 반쪽 선 둘, 반쪽마다 제 끝의 `Pressure`만큼 채도를 잃는다(`LaneColorOf` — 1에서 회색, 알파는 1 그대로). 색은 고정이다(맥동하려면 프레임마다 다시 그려야 한다). 물리 시야는 오늘처럼 레인마다 선 하나이고, 그린 레인의 수는 선이 아니라 레인을 센다.
- **하늘**: `M_Nebula`의 스칼라 `SpiritualIntensity` 하나(맵 액터가 하늘의 동적 인스턴스에 준다 — `SkyIntensityOf`): 물리 0, 영적 1. 1에서 하늘은 채도를 잃고 어두워져 보라를 내놓지 않는다(주인 고리도 타락의 띠를 피한다 — 위 '네 색'). 노이즈 노드는 하나 그대로다(하늘은 화면 전체의 패스다).
- **패널의 말**: 영적 시야에서 성계 패널은 표식의 말을 상세 줄 아래 제 글 한 줄과 그 줄의 툴팁으로 보인다 — 상세 글과 따로라서 줄도 툴팁도 백성의 규모 줄('{PopBand} 백성')을 덮지 않는다(주장은 크기와 함께 말하지 않는다 — §8.4. 7번 작업의 리뷰에서 한 덩이의 툴팁이 규모 줄까지 덮었다). 호칭(`FTranscendentDef.Title`)만, 숫자·비율 없음, 흰 글, 네 말이 모두 곳을 부른다: "{호칭}이/가 주장하는 곳"(주장 중 — 목적어 없는 '주장함'은 두 줄 위의 '수천억 백성'을 목적어로 읽혔다), "…붙든 곳"(편입), "…묶이기 전에 붙든 곳"(결박 — 결박을 이긴 일로 말하지 않는다, §8.3), "…누르는 곳"(누르는 자 — §4.2 모방의 원리의 동사 '붙들고·누르고'). 조사는 엔진의 한국어 수식자 `|hpp(이,가)`가 고른다. 표식이 없거나 호칭이 비면 말이 없다. 물리 시야에는 줄도 툴팁도 없다. 툴팁은 말이 바뀔 때만 다시 준다(패널은 틱마다 다시 그린다 — 새 툴팁은 열린 것을 닫는다). 호칭은 Phase 3 7번 작업에서 데이터에 들어왔다(`trans_silence` "꺼뜨리는 이" — §4.2 교리 표의 둘째 호칭. 첫 호칭 "잠잠케 하는 자"는 §5.11의 어휘 분리와 부딪쳐 바꿨다, §16 #99).
- **미룬 것**: (앎의 문은 8번 작업이 걸었다 — 모르는 성계에는 표식·맥동이 없고, 두 끝을 아는 레인만, 보이는 주인의 '백성' 줄만, 위 '앎의 표시'.) `NS_TranscendentAura`(Niagara — §6.5, 넷째 칸부터의 물리 시야 오라도), 타락이 아닌 압력의 그림(독립 초월자 — §16 #98). 셋째 칸 직후의 첫 내용이 주장 표식이 되게 하는 가중은 Phase 4 데이터다(§4.2 '표식').

## 9. 저장, 결정론, 테스트, 밸런스

초안에 없던 장이지만 Phase 1부터 들어가야 한다. 나중에 붙이면 전체 리팩터링이 된다.

### 9.1 저장/로드

`UCosmicSaveGame : USaveGame { UPROPERTY() FGalaxyState State; }` 하나.
상태가 전부 USTRUCT이므로 `UGameplayStatics::SaveGameToMemory`의 바이트를 슬롯의 꼴(검사하는 64바이트 머리·Oodle 압축·디스크까지 내린 쓰기와 백업 하나 — `Save/CosmicSaveSlot.h`, 헤더 `docs/60_DECISIONS/headers/A5_save_minimum.md` §3)로 쓴다(MVP ⑤ A-5a, 2026-10-23). Actor나 위젯 상태는 저장하지 않는다. 로드 후 Presentation이 상태를 보고 다시 그린다.
`SaveVersion`을 두고, 구조체 필드 추가 시 기본값으로 호환한다. 필드 삭제·의미 변경은 버전 올리고 마이그레이션 함수를 쓴다. 저장된 필드의 기본 초기값(멤버 초기화식)도 세이브가 생긴 뒤에는 바꾸지 않는다(의미 변경으로 취급한다): 엔진의 저장 바이트(`SaveGameToMemory`)는 클래스 기본 객체 대비 델타이므로 `FGalaxyState`·`Player`·`Calling`의 직속 멤버(와 그 안에 직접 든 구조체의 멤버)는 초기값과 같으면 기록되지 않고, 로드하는 빌드의 초기값으로 읽힌다(`TArray` 원소 구조체는 전부 기록된다). 같은 이유로 `SaveVersion`의 초기값은 리터럴 1로 고정하고(= 버전 태그가 없는 세이브가 읽히는 버전) 현재 버전 `FGalaxyState::CurrentSaveVersion`은 `NewGalaxy`와 마이그레이션이 찍는다 — 초기값을 그 상수에 묶으면 버전이 한 번도 기록되지 않아 첫 버전 인상 뒤 구 세이브가 새 버전으로 읽히고 마이그레이션이 돌지 않는다(UE 5.8.3 소스 확인: `GameplayStatics.cpp` `SaveGameToMemory`, `Class.cpp` `SerializeTaggedProperties`). Phase 1의 개발 세이브와, v0.7 예약 커밋부터 Phase 2 은하 생성 규칙 변경 사이에 만든 세이브는 넘기지 않는다(그런 세이브의 `Knowing`에는 출생 문명이 없어 첫 갱신이 제 백성을 첫 접촉으로 만날 것이다 — 고치는 코드를 두지 않는다, 아는 범위와 로그 작업의 리뷰) — 배포된 세이브가 없고 `SaveVersion`은 1 그대로이며, `Sim.SaveRestart`는 바이너리가 바뀌면 기록을 새로 쓴다.
**슬롯 정책: 판당 슬롯 1개(아이언맨).** 슬롯 이름은 `FGalaxyState.GalaxyID`에서 만든다(`Galaxy_<GUID>` — 이름은 그대로 두고 판의 신원으로 읽는다). 수동 저장·로드 메뉴는 없다. 사망 직전 세이브를 로드할 수 있으면 하드 리셋이 선택 사항이 되어 부름과 계승(§4.4) 전체가 무의미해진다. 결정론(§9.2) 덕에 비용은 정책 수준이다. "관조 모드" 토글(수동 저장 허용)은 Phase 5 테스터 반응 뒤 결정한다(§16).
**자동 저장 트리거**(MVP ⑤ A-5c, 2026-10-23 — 헤더 `docs/60_DECISIONS/headers/A5_save_minimum.md` §4): 틱 경계(`OnSimTick` — '역할 효과 해소' 단계와 `SyncRngState` 뒤, 알림의 괄호 밖, §7.4)에서 저장 층이 디스크 사본(`FCosmicSavedMark` — 마지막으로 쓰거나 읽은 슬롯이 든 것: 판·틱·상태 해시·업적 수·역할·다스리는 백성·끝·실제 시각. 저장도 해시도 아닌 디스크의 캐시다)과 지금을 견주어 쓸 까닭 하나를 고른다(`UCosmicSaveSubsystem::DueAt` — 다른 판 `NewRun` > 임시 끝이 섰다 `Ended` > 업적 수 `Ascended`(승천 직후) > 역할·다스리는 백성 `Role`(폐위, 그리고 B1의 양위·즉위·복귀도 같은 비교가 받는다) > 마지막 쓰기나 로드부터 실제 시간 600초가 지났고 틱이 움직였다 `Interval`(10분마다); 경계마다 많아야 한 번). 입력 때 곧바로 쓰는 셋: 받아들인 청원의 답(`AnswerPetition` — 강제 종료 뒤 같은 카드를 다시 굴리는 길을 닫는다), 새 판(게임 시작의 새 은하와 연대기의 '새 판'), 종료(강제 종료 롤백 방지 — 창 닫기·Alt+F4는 게임 뷰포트의 `OnCloseRequested`: 창을 닫으면 로컬 플레이어가 지워지며 컨트롤러가 `EndPlay(Destroyed)`로 먼저 끝나 `Quit`을 보지 못한다; 콘솔 `quit`·`RequestExit`는 `EndPlay(Quit)`. 슬롯이 이미 같은 상태(상태 해시)를 들고 있으면 쓰지 않는다). 핸들러나 틱 단계 안에서 청한 저장(`RequestSave`)은 다음 경계로 미룬다(`SaveCurrentGalaxy`는 거기서 에러 한 줄로 거절된다). 시간이 멈춘 동안에는 경계가 없고, 헤드리스 도약은 알림 문이 닫혀 쓰지 않는다. 프로젝트 시작은 쓰지 않는다(추첨이 없는 입력이라 10분과 종료가 받는다). (Phase 4b) **사망 직후**(공백기 진입 시, `PendingLeapTicks` 포함)·**계승(취임) 직후**·귀환 제안의 선택 뒤는 Phase 4b 헤더가 `BeginInterlude`의 명시 저장 지점으로 두고 디스크 사본에 생애 수와 `LifeState`를 더한다. 사망과 계승 사이(공백기 도약 중)에는 저장하지 않고 진입 시 저장한 `PendingLeapTicks`로 재개한다(`Calling.LeapResumeRoundTrip` 테스트, §9.3).
**슬롯·백업·이어하기**(MVP ⑤ A-5a·A-5c, 2026-10-23 — 헤더 §3·§5): 슬롯 하나는 64바이트 머리(첫 낱말 `CASV`·꼴 1·코덱·GalaxyID·쓴 시각(UTC)·틱·두 길이·페이로드 CRC·머리 CRC — 첫 낱말·꼴·GalaxyID·쓴 시각·머리 CRC의 자리는 모든 꼴에 고정된 봉투다)와 Oodle(Kraken·VeryFast)로 줄인 엔진 바이트다(코덱이 실패해 0을 내면 줄이지 않고 그대로). 읽기는 길이와 두 CRC를 엔진의 읽기 함수(`LoadGameFromMemory`)보다 먼저 본다(#70). **쓰는 차례**: 검사를 통과한 슬롯을 `_bak`으로 옮겨 쓰고 디스크까지 내린 뒤(`IPlatformFile` 손잡이의 `Flush` — Win64 `FlushFileBuffers`) 슬롯을 쓰고 내린다 — 어느 순간에 꺼져도 좋은 사본 하나가 디스크에 있다. 머리의 쓴 시각은 이 프로세스가 쓰거나 읽은 어느 머리의 시각보다 늦다 — 시계가 뒤로 가도, 슬롯 쓰기가 실패해도 그 시각은 쓴 것으로 센다(이어하기가 이 시각으로 판을 고른다). 읽히지 않는 슬롯(잠금 — 0.25초 뒤 한 번 더 읽어 본다)과 새 꼴의 슬롯은 덮지 않고, 상한 슬롯은 옮기지 않으며(백업이 남는다), 성역을 지키지 않은 상태는 쓰지 않는다(읽기와 같은 술어 `CosmicSave::KeepsSanctuary` — 시뮬의 결함이 백업까지 밀어내지 않게). **로드**는 슬롯이 상했거나 없을 때만 백업을 연다 — 읽히지 않음·새 꼴·새 버전·성역 거절은 백업을 열지 않고 거절하고, 거절된 로드는 시뮬을 건드리지 않는다. **이어하기**(`ContinueNewest`): 게임 시작(`ACosmicGameMode::StartPlay`, `Super::StartPlay` 앞 — 핸들러가 묶이기 전이라 두 `BeginPlay`가 상태를 읽는다)에 슬롯 폴더의 파일마다 머리 64바이트만 읽어 가장 새 판(머리의 쓴 시각 — 잘린 슬롯과 새 꼴의 머리도 시각을 댄다, 머리가 읽히지 않으면 파일 시각; MVP ⑤ 전의 엔진 꼴 슬롯은 판으로 세지 않는다)을 그 슬롯이나 백업에서 연다. 그 판이 열리지 않으면 더 옛 판으로 내려가지 않고 새 판을 연다 — 그 새 판은 첫 틱 경계가 쓰고, 그 전에 끄면 종료 저장도 건너뛰어 다음 시작이 읽지 못한 판을 다시 본다(헤더 결정 6). 아무것도 지우지 않는다. 이어 연 판은 멈춘 채 열리고 상단 바에 까닭 줄('정지 — 하던 판을 이어 열었다'·'정지 — 그 앞의 저장으로 이어 열었다'·'정지 — 저장을 읽지 못해 새 판을 열었다')이 선다 — 개발용 `-Speed=N`은 이 정지를 건너뛴다. 끝난 판은 끝난 채(래치·다 드러난 쪽) 연다. **실패**: 게임 길의 쓰기가 실패하면 게임 인스턴스마다 처음 한 번 시간을 멈추고 '정지 — 이 판을 저장하지 못했다'를 띄운다(컨트롤러가 그 틱 경계나 입력 직후에 보기 전에 다른 쓰기가 바로잡았으면 띄우지 않는다. 끝난 판에서는 띄우지 않는다). 실패한 까닭은 남아 실제 60초 뒤의 첫 경계가 다시 쓴다 — 임시 끝(`Ended`)만은 기다리지 않는다(래치가 그 틱에 시간을 멈춰 다음 경계가 오지 않는다). 성공한 쓰기는 어느 길이든 남은 까닭과 기다림을 지운다. **게임 저장의 문**(`IsGameSavingOn`): 시작의 이어하기·경계의 자동 저장·입력과 종료의 저장은 `-NoSave`·`-unattended`·`-Seed=`·에디터 프로세스(`GIsEditor` — 에디터 안 플레이는 저장하지 않고 Standalone Game·`-game`·패키지는 저장한다)·자동화 테스트 중에는 하지 않는다. 명시 호출(`SaveCurrentGalaxy`·`LoadGalaxy`·`ContinueNewest`·`DeleteSave` — 테스트·도구)은 문을 보지 않는다. 테스트의 슬롯은 `Saved/SaveGames/Automation/` 아래에만 쓴다(`PrepareForTests` — 게임의 이어하기는 하위 폴더로 내려가지 않는다). **패키지의 자리**(MVP ⑨): 슬롯과 로그는 `ProjectSavedDir()` 아래다 — 구성마다의 자리는 `docs/45`의 `FPaths::ProjectSavedDir` 행. 해시 판(`-CosmicHashRun`, §9.2)은 `-Seed=`를 요구하고 저장 문이 열려 있으면 거절하며 `BeginSession` 전에 끝난다 — 슬롯을 읽지도 쓰지도 않는다.

**난수의 출처 셋**: 난수의 출처는 셋뿐이다 — ①②는 `UGalaxySimulationSubsystem`이 주고 ③은 `Core/CosmicSeed.h`의 순수 함수다.

① **시뮬 스트림** `GetRng()`(= `RngState`): 저장되는 세계 상태를 바꾸는 모든 추첨 — 생성, 틱 단계, 건넘의 착지, 계승과 도약, 조우 판정(카드의 답 — 받아들인 답마다 1회, 청원과 방랑자 카드가 같다), 인물과 그릇의 이름(양위의 열째 단계는 섭정 성향과 섭정 이름 2회 — B1).

② **말하기 스트림**(= `TellRngState`, int32 하나): `UCosmicLogSubsystem::PushVariants`의 문장 변형 추첨만 — `DrawTell`을 부르는 함수는 이것 하나다(`PushRow`는 그 포장이고 `PickTemplateRow`는 뽑지 않는다). 살아 있는 스트림 객체를 두지 않는다 — `uint32 DrawTell(int32 Count)`가 `TellRngState`로 지역 스트림을 열어 한 번 뽑고 상태를 되적는다. 어떤 규칙도 ②를 읽지 않고, 말하기는 ①을 뽑지 않는다. `PushVariants`는 줄이 쌓이든 아니든 호출당 ②에서 정확히 1회 뽑는다(거절된 호출 — 빈 변형, 핸들러 안 — 은 뽑지 않는다. 마지막으로 말해진 줄과 같으면 — `bUntold` 항목은 건너뛴다 — 다음 변형으로 넘기고 다시 뽑지 않는다). 예외는 하나다: 범위 밖의 Severity 2 줄을 대신하는 먼 줄(§8.1)은 안에서 부르는 둘째 `PushRow`이고 제 몫의 추첨을 한 번 한다 — 그 호출은 2회다. `PushRow`의 반환값은 범위에 좌우되지 않는다(행이 없거나 템플릿이 비면 추첨 없이 false, 그 밖에는 true).

③ **파생 정수** `CosmicSeed::Derive`(아래 '시드와 파생'): 상태 없는 순수 함수 — 요약 은하의 값과 출발 일정, 건너온 백성의 이름과 아키타입, 성계의 생명 낱말, 표현 계층의 그림(배경 별·풍경 은하), 문명의 이벤트 슬롯 위상(§7.5), 청원 카드의 고르기(MVP ② — 고른 결과는 앎(`Knowing.PendingPetitionRow`)에만 쓰이고 세계를 바꾸는 것은 플레이어의 답이다, §5.10), 방랑자 카드의 몫과 고르기(B1 — Encounter, 같은 까닭).

②③은 ①을 뽑지 않고 ①에 씨를 주지 않는다. ③의 값이 시뮬 규칙의 일정을 정하는 곳은 둘이다 — 요약 은하발 출발 일정(Depart, §7.4)과 문명의 이벤트 슬롯 위상(EventSlot, §7.5): ①의 고정 추첨이 어느 틱에 놓이는지를 정할 뿐이고, 둘 다 Seed와 이름만의 함수라 앎·이야기·표현에 좌우되지 않는다. `Check`·`Apply`·`EvaluateAndFire`는 `GetRng()`를 직접 부르지 않고 문맥이 건넨 스트림을 쓴다(은하별 스트림은 둘째 상세 은하를 만들 때 이 절을 고쳐 더한다 — 지금은 두지 않는다). `FMath::Rand*`를 시뮬 코드에서 쓰면 설계 위반이고 추첨은 틱 순서의 고정 지점에서만 한다 — 둘 다 그대로다. 추첨 지점의 규칙 셋: ⓐ 지점은 무조건 뽑는다 — 후보가 없어도, 테이블이 비어도 뽑고 버린다(`RandHelper(0)`은 뽑지 않으므로 후보 수로 호출을 가르지 않는다) ⓑ 같은 처리 안의 추첨은 묶어서 먼저 뽑는다 — 이벤트 슬롯은 그 틱의 수를 전부 뽑은 뒤 행을 보고, 위기의 발생은 성계마다의 수를 전부 뽑은 뒤 Hazard를 놓는다 ⓒ `NameNotable`·`Notable.Ascendant`·그릇(`Install`)의 이름은 적용마다 정확히 1회, 가드와 뱅크보다 먼저다(틱당 원천은 `NameNotable`을 걸지 않는다 — 걸리지 않은 효과는 적용이 아니고 추첨도 없다, §7.5). 그래서 추첨 지점마다 뽑는 수는 시드·틱·소유와 세계에 일어난 일만 따르고 `DT_Events`의 행 수·조건·가중치·쿨다운과 이름 뱅크·Tier·상한에 좌우되지 않는다(이름 뱅크·Tier·상한은 `NameNotable`·`Notable.Ascendant`·`Install`의 가드를 두고 하는 말이다 — AI 단계의 정착 추첨은 정착할 수 있는가(`MaySettle`)를 따르므로 백성의 정착된 성계·소유 성계 수·진행 중 정착과 그 Tier의 `RealmCapByTier`를 읽는다. 정착 행·대상·지형은 읽지 않는다) — 발화한 행이 `NameNotable`을 실었으면 그 적용마다 1회가 더해지고(행의 효과 목록이 정한다), 만료·폐위처럼 일어난 일마다 뽑는 지점은 그 일이 일어난 수만큼 뽑는다. 그 일이 언제 몇 번 일어나는지는 세계를 따르고 세계는 테이블의 값(카운트다운·확률·조건·Stability)을 따르므로, 테이블의 값을 바꾸면 같은 시드의 역사도 바뀐다 — 바뀌지 않는 것은 한 지점이 한 번에 뽑는 수다. `Check`가 받는 뷰에는 스트림이 없다(§7.5). Phase 2 뒤의 틱 안 추첨 지점: 위기 단계의 만료(모은 만료마다 2회 — 결과의 수와 주장의 수. Hazard의 종류와 행의 유무에 좌우되지 않는다), 발생(정착된 성계마다 1회 — 슬롯이 찼든 비었든), 역할 효과 해소 단계의 폐위(섭정 프로필 1회), 이벤트 슬롯(슬롯을 받는 문명마다 1회), `NameNotable`(적용마다 1회), AI 단계의 정착 추첨(정착을 시작할 수 있는 AI 백성마다 1회, 대상을 보기 전에 — 대상이 없어도, 정착 행이 없어도. 정착과 문명 제거 작업)과 업적 판정의 인물 이름 — 분쟁·조우·계승의 지점은 Phase 4·4b에 더한다(§11). 틱 밖의 지점 하나(MVP ②): 청원의 답(`UPlayerRoleSubsystem::AnswerPetition`)은 받아들인 답마다 ①에서 판정의 수 1회(0~5)를 뽑는다 — 선택지의 판정·비용·조건을 보기 전에, 판정 없는 선택지와 때가 지난 카드에서도. 거절된 답(대기 카드 없음·선택지 번호 밖·비축 부족·방송 중)은 뽑지 않는다. 카드를 내놓는 일은 ①을 뽑지 않는다(③ `Petition`). 추첨 없는 틱 밖 입력은 프로젝트의 시작(`StartMegaproject`)과 연구 중점(`SetResearchFocus`, MVP ⑦)이다 — 세계를 바꾸지만 뽑지 않는다(같은 시드·같은 틱의 같은 입력이면 같은 두 해시).

해시: `RngState`는 지금처럼 살아 있는 스트림 값으로 대체하고, `TellRngState`는 저장 값(항상 최신)을 그대로 읽는다. `TellRngState`의 멤버 초기값 0은 동결이고 `NewGalaxy`가 값을 찍는다. `ComputeStateHash()`는 전부를, `ComputeWorldHash()`는 `Knowing`·`Log`·`Chronicle`·`ChronicleEviction`(MVP ⑤)·`TellRngState`를 뺀 것을 해시한다(§8.1).

'v0.7 예약' 커밋(§11)에서 함께 하는 일: `PushRow`를 말하기 스트림으로 옮긴다. `Log.NoConsecutiveRepeat`의 스트림 탐침 3곳을 `TellRngState`로 옮긴다('호출당 1회' 단언 유지). `Sim.SaveRoundTrip`에 `TellRngState`가 이어지는지의 단언을 더한다. 새 테스트 `Sim.TellStreamSeparate`(`PushRow` 전후 `GetRng().GetCurrentSeed()` 불변, `TellRngState`만 전진).

**v0.8과 추첨**: 서막은 추첨이 없다(바꾸려면 조우 판정과 같은 입력 열의 자격 — ①). 성역은 추첨 없이 배열 끝에 붙는다(단계 4 — 수가 바뀌지 않는다). 실제 하늘(단계 5 — 태양 근방 관측 목록의 계와 행성으로 짓는 지도)은 생성 추첨 목록을 바꾸고 Phase 5 전에 모든 시드를 한 번 바꾼다(새 기준값) — '시뮬 추첨 지점은 테스터와 시드를 나누기 전에만 더한다'(§11)를 지킨다. 시간 표시는 시뮬 스트림을 쓰지 않는다. 그 백성이 제 별을 부르는 이름은 `CosmicSeed::Derive`다(단계 5 — 시뮬 추첨 없음).

**시드와 파생**: 한 판 = 우주 시드 1개 = 부름 1회 = 4~6시간, 기대 2~5대(길이는 그대로다). 플레이어가 넣는 시드는 `FGalaxyState.Seed` 하나뿐이다(필드, `-Seed=`, `NewGalaxy(Seed, SystemCount, CivCount)` 시그니처 그대로). 은하마다 시드를 받지 않고, 시작 은하나 시작 규모를 고르는 화면은 없다 — 첫 생애는 우리은하의 성역 밖(태양계 바깥) 한 별이다(`sys_0` — v0.8 — 단계 4부터. 그 전의 코드는 태양계 `sol`). 고향 은하(`DT_Rules.HomeGalaxyRow`, 기본 `gal_milkyway`)는 시뮬 스트림 `Initialize(Seed)`에서 생성된다. 그 밖의 모든 파생값은 `CosmicSeed::Derive`(`Core/CosmicSeed.h`)에서만 나온다. 은하는 언제나 `DT_Galaxies` 행 이름으로 가리키고 은하별 시드는 저장하지 않는다(파생) — 행을 더하거나 순서를 바꿔도 다른 은하의 값이 움직이지 않는다. 은하 행 이름과 `HomeGalaxyRow`는 세이브에 닿는 다른 행 이름처럼 배포 뒤 바꾸지 않는다(§10.4). 시계는 `Tick` 하나다(은하별 시계 없음).

`CosmicSeed::Derive`는 모듈 안의 인라인 함수 하나이고 부호 없는 32비트 산술만 쓴다(넘침은 그대로 감긴다. `GetTypeHash`·엔진 CRC·부동소수점 금지). 식과 상수는 여기 적힌 그대로 동결한다:

```
uint32 Derive(int32 Seed, FAnsiStringView LowerAsciiName, uint32 Purpose, uint32 Index = 0)
  h = 0x811C9DC5
  for each byte b of LowerAsciiName:  h ^= b;  h *= 0x01000193        // FNV-1a 32
  h ^= (uint32)Seed;   h *= 0x9E3779B1
  h ^= Purpose;        h *= 0x85EBCA6B
  h ^= Index;          h *= 0xC2B2AE35
  h ^= h >> 16;  h *= 0x85EBCA6B;  h ^= h >> 13;  h *= 0xC2B2AE35;  h ^= h >> 16
  return h
```

용도는 고정 상수이고 번호를 다시 매기지 않는다: Tell 1(말하기 스트림의 시작값), Summary 2(요약 은하), Name 3(건너온 백성의 이름), Life 4(성계의 생명 낱말), Backdrop 5·Scenery 6(표현 계층의 그림), Depart 7(요약 은하발 출발 일정), Archetype 8(요약 은하발 건넘의 아키타입), EventSlot 9(문명의 이벤트 슬롯 위상 — 이름은 CivID, §7.5), Petition 10(청원 카드의 고르기 — 이름은 다스리는 백성의 CivID, Index는 틱, §5.10), Encounter 11(방랑자 카드 — 도착 카드의 몫과 다시 편 값의 고르기, 서 있는 행의 고르기; 이름은 그릇이 선 SystemID, Index는 틱, B1). 새 용도는 끝에 더한다(안전하다). 인자를 더하는 일은 기준값이 생긴 뒤에는 안전하지 않으므로 `Index`를 처음부터 둔다. Tell의 이름은 빈 문자열이고, 그 밖의 이름은 행 이름이나 ID를 소문자 ASCII로 쓴 것이다. 파생 값으로 스트림을 열 때는 `FRandomStream::Initialize((int32)Value)`를 쓴다. `TellRngState`는 `NewGalaxy`가 `(int32)Derive(Seed, "", Tell, 0)`으로 찍는다.

`Sim.SaveRestart`의 기록에 Derive 값 하나를 더해 두 프로세스에서 같은지 본다(두 절반이 같은 바이너리라 구조상 같다 — 값을 쥐는 것은 `Sim.SeedDerive`와 헤더의 `static_assert`다). v0.7에서 같은 시드가 주는 은하는 달라진다(골든 해시가 없어 깨지는 테스트는 없다). 이 변화는 Phase 2의 은하 생성 규칙 변경 한 번으로 묶고 테스터와 시드를 나누기 전(Phase 5 전)에 끝낸다.

틱 내부 처리 순서는 고정(§7.4 주석). `TMap` 순회로 결과가 달라지는 코드를 쓰지 않는다. 순서가 중요한 곳은 `TArray`를 정렬해서 쓴다. `TMap`은 한 판 안에서는 순서가 결정적으로 보여도, 원소를 지운 뒤 새로 넣으면 실행 중에는 빈 자리를 재사용하고 로드 뒤에는 끝에 붙어 저장·로드 전후의 순회 순서가 달라진다 — 키를 `FNameLexicalLess`로 정렬해 쓰거나 `Civs`·`Transcendents` 배열을 돌며 `Find`한다.
같은 시드 + 같은 플레이어 입력 시퀀스 → 같은 `ComputeStateHash()`. 이것이 테스트의 기준이다. 해시에는 `Calling`(생애 인덱스·상태·기록)이 포함된다. 해시는 FName·숫자·태그만 포함하고 모든 FText(`Log`·`Chronicle`의 `Message`, `DisplayName`, `CivName` 등)를 제외한다 — 로그 항목은 Category·Severity·Tick·SourceRow·FocusSystemID·FocusCivID·bUntold만(§4.4의 FText 저장 원칙과 같은 이유. 로컬라이제이션만 바뀌어도 Determinism 테스트가 깨지는 것을 막는다). `FLifeRecord.SuccessionKind`·`bReturnOffered`·`BirthArchetypeRow`는 포함한다. `FCivilizationState.Notables`(Role·NameIndex·FirstTick·LastTick·SourceRow — 정수·태그만)와 `FLifeRecord.NameIndex`도 포함한다. 규모 등급(`GetPopulationBand`)은 파생값이라 해시에 없다. 사망 파이프라인·계승 추첨·공백기 도약의 추첨도 전부 시뮬 스트림 `GetRng()`를 통한다(§4.4. 그 줄들의 문장 변형은 말하기 스트림이다). 인물의 이름 추첨(`NameNotable` 가드·`Install()`)도 시뮬 스트림만 쓰며(`Apply`는 문맥이 건넨 스트림으로, 적용마다 1회 제 가드보다 먼저), 틱 순서 안의 고정 지점(`UCosmicEventSubsystem::Apply`, `TickHazards` 만료 처리, `UAscensionSubsystem` 판정, 역할 효과 해소 단계의 `Install`) 또는 조우·청원 해결(틱 밖 플레이어 입력 — 판정 난수와 같은 자격으로 입력 시퀀스의 일부)에서만 일어난다. 같은 시드와 같은 입력 시퀀스면 같은 명부. `Notables`는 `TArray`이고 퇴출 선택은 (LastTick, FirstTick, 배열 순서) 키라 `TMap` 순회 없음. **해시의 표준형**: `FName`과 `FGameplayTag`는 소문자로 바꾼 문자열로 해시한다 — `GetTypeHash(FName)`·`GetTypeHash(FGameplayTag)`·이름 인덱스·구조체 원시 메모리는 프로세스마다 값이 달라, 한 프로세스 안의 `Sim.Determinism`·`Sim.SaveRoundTrip`은 통과해도 "저장 → 재시작 → 로드 → 해시 동일"(§11 Phase 1 종료 조건)은 깨진다. `TMap`은 `FNameLexicalLess` 키 순서로, `FGameplayTagContainer`는 명시 태그만(파생 부모 태그 제외) 해시한다. `FGalaxyState.GalaxyID`는 저장 슬롯의 신원이라 해시에서 제외한다 — `NewGalaxy`가 `FGuid::NewGuid()`로 만들고(`GetRng()`를 쓰지 않는다) 같은 시드의 두 판도 값이 다르다. 시뮬이 읽는 FText는 없다 — 모든 AI 문명은 생성 때 이름을 받고(§5.11), 돌파 줄이 말해지는가는 이야기의 범위가 정한다(§8.1). `ComputeWorldHash()`는 `ComputeStateHash()`에서 `Knowing`·`Log`·`Chronicle`·`ChronicleEviction`(MVP ⑤)·`TellRngState`를 뺀 해시다(최상위 멤버 이름 기준) — 앎이 세계를 바꾸지 않음을 재는 자이고(`Sim.KnowingInert`, §8.1) 쿠킹 빌드는 이것과 전체 해시 둘로 견준다(같은 말하기 모드 — MVP ⑨). `Knowing`은 전체 해시에 들고 세계 해시에는 들지 않는다.
결정론의 보상: 버그 재현, 리플레이, 헤드리스 밸런스 측정이 모두 가능해진다. 테스트와 밸런스 커맨드렛(에디터 바이너리)이 게임 바이너리와 같은 시드에서 같은 해시를 내도록, 게임 모듈은 모든 타깃에서 부동소수점을 정밀 모드로 컴파일한다(`Build.cs`의 `FPSemantics = FPSemanticsMode.Precise`. V7 기본값은 에디터 타깃만 정밀이고 게임 타깃은 `/fp:fast`다). 해시에 들어가는 부동소수점 값은 이 모듈 안에서 컴파일되는 코드로만 계산한다 — 엔진 모듈의 비인라인 함수(예: `FLinearColor::MakeFromHSV8`)는 타깃의 부동소수점 모드를 따르므로 쓰지 않는다(AI 문명 색은 모듈 안의 같은 산술로 낸다). 모놀리식 게임 exe에서는 인라인되지 않은 헤더 함수·템플릿도 링크에서 엔진의 `/fp:fast` 사본을 탈 수 있다(COMDAT — 엔진 목적 파일이 먼저 링크된다, `docs/45`) — 그래서 Core Logic이 부르는 `FMath`는 짧은 허용 목록(`Tools/check_layers.py`의 `MATH_ALLOWED` — 인라인의 + − × ÷와 √)뿐이고 C 런타임 수학은 `sqrt`뿐이다. `check_layers.py` 규칙 3b가 이 철자들을 본다(`FMath`는 허용 목록, C 런타임은 이름을 댄 함수의 거부 목록 — MVP ⑨). 헤더의 벡터·난수 도우미는 린트 밖이다: 지금 해시에 드는 것은 강제 인라인 `FVector::DistSquared`(레인 고르기)와 `FRandomStream`(정수 셈과 오차 없는 변환 — ⓓ가 확인했다)이고, 새 도우미는 강제 인라인인지·+ − × ÷ √뿐인지 엔진 헤더에서 확인하고 쓴다. 해시에 드는 값은 + − × ÷ √만 쓴다(`sqrtf`는 정확히 반올림된다). 삼각 함수를 비롯한 다른 C 런타임 수학 함수는 쓰지 않는다 — 성계 배치는 원판 안 기각 추출이다(§7.4). 기각 추출은 성계 하나에 16번까지 시도하고, 16번째 점도 원판 밖이면 그 점의 좌표를 절반으로 줄여 쓴다(정사각형 안의 점은 절반으로 줄이면 언제나 원판 안이다. 16번 내리 빗나갈 확률은 성계 하나에 약 2 × 10⁻¹¹이다 — 상한은 루프를 묶으려는 것이다). 해시에 드는 산술은 모듈 안 코드로만 한다(`FMath::Pow`·비인라인 `FVector` 도우미 금지). 코드의 `FMath::Cos`·`FMath::Sin`은 Phase 2 은하 생성 규칙 변경 커밋에서 한 번에 지웠다. `SummaryAt`은 시뮬 규칙이다(§7.4) — 이 수학 규칙을 따른다. 현실 수치(§3.4)와 닿는 것 가운데 해시에 드는 것은 셋뿐이다(§7.4): 항성 등급(`DT_Rules.LivingWorldStarShares` — 설계 값), `sys_0`의 고정 자리(`FGalaxyDef.HomeRadiusShare` — v0.8 — 단계 4부터. 그 전의 코드는 `sol`), 성계 좌표(v0.8 — 단계 5 뒤에는 관측 목록의 좌표·등급이 해시에 든다 — 오프라인 도구가 계산한 값). 나선팔·막대·광년 눈금·배경 별·풍경 은하는 표현 계층이 그린다(해시 밖). 게임 바이너리에서의 해시 일치는 MVP ⑨에서 확인했다(2026-10-24, 헤더 `docs/60_DECISIONS/headers/A9_win64_packaging.md` §1.7): 쿠킹한 Development 빌드가 시드 42의 입력 없는 판과 통치자 정책 판에서 에디터와 같은 두 해시(세계·전체 — 같은 말하기 모드)를 3,000·20,000틱 모두에서 낸다. 쿠킹 빌드의 해시는 커맨드렛(게임 exe가 거절한다)이 아니라 게임 스위치 `-CosmicHashRun`(`World/CosmicHashRun` — `StartPlay`의 맨 앞, 정책 판은 커맨드렛과 함께 쓰는 `World/CosmicRulerPolicy`)이 내고, `run_checks.ps1`이 매번 에디터의 해시 판 = 커맨드렛을, `Tools/package.ps1`이 패키지 = 에디터를 본다. 되풀이하는 때: 마일스톤마다의 끝, B8(기준값 다시 잡기), Phase 5 테스터 빌드 전, `Build.cs`·`Target.cs`의 컴파일 설정이나 엔진 버전을 바꾼 뒤.

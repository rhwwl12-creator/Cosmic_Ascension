# A5 — 로드맵·워크플로 (프로듀서 겸 리드)

## 0. 전제 바로잡기

로드맵이 **없는** 것이 아니다. 로드맵이 **세 벌**(guideline §11 상태 줄, CLAUDE.md '현재 단계', WORKPLAN §3+부록 A)이고 번호 체계가 **넷**(Phase 0~6b / v0.8 단계 0~8 / WORKPLAN 표 번호 1~12 / §16 #1~#95)이라 "지금 어디이고 다음이 무엇인가"를 한 곳에서 읽을 수 없는 것이 문제다. CLAUDE.md:278과 WORKPLAN.md:200의 '다음' 문단은 자구가 같고, guideline §11은 주 단위 일정(P1 2주·P2 3주+8~9일·P3 4주+5일, 수직 슬라이스 약 8개월, EA 12~18개월, guideline.md:3861-3863·3998)을 적지만 **실제는 P1 종료 10-12, P2 10-13~17, P3 1~6·11번 10-17~18** — 계획 약 9~10주치가 8일에 끝났다. 일정 열은 의사결정에 쓸 수 없는 숫자다.

## 1. 지금 빌드와 Playable MVP의 거리

**지금 빌드**: 지도 보기·선택·배속·거대 프로젝트 시작·정착·로그 읽기·승천 연출(T1→T3). 검증 결과 **판이 끝나지 않고 저장되지 않는다** — 엔딩 검사 없음(`RunHeadless` 주석만), `Effect.KillPlayer`는 기록된 채 남음(GalaxySimulationSubsystem.cpp:2215-2228), `SaveCurrentGalaxy`를 부르는 게임 코드 0건(테스트·커맨드렛만), 외교·분쟁 단계는 빈 함수(:1585-1593). 플레이어의 '결정'은 단추 두 종류뿐이고 첫 600틱에 말해진 줄은 중앙값 9(목표 25~40, guideline.md:3692).

**MVP 정의(판단)**: 통치자 단일 모드, 첫 생애 한 번, 30~60분(1배속~×10 혼용), 끝이 둘 이상.

## 4. 세션 워크플로 재정립

- **작업 단위**: '컴파일되는 상태 + 테스트 2회 연속 통과' 유지. 1세션 = WORKPLAN 행 하나.
- **헤더→리뷰→소스**: 골격 유지, **적용 범위를 좁힌다** — 저장 필드·열거형·틱 단계 본문·결정론 코드만 헤더 승인. UI·데이터 행·버그 수정은 생략(이미 10-17부터 자가 승인 중). 승인 초안은 gitignore된 `Saved/Design`(이 체크아웃에 없음)이 아니라 저장소 `Docs/design/`에 둔다.
- **ultracode 투입 기준(명문화)**: 켬 = ① 세이브·해시에 닿는 변경 ② 틱 단계 신설 ③ 텍스트 묶음 ≥ 20문장 ④ 단계 종료 리뷰. 끔 = UI, 행 추가(검사기가 대신), 버그. WORKPLAN §0 3항('켜지기 전 단독 진행 금지')은 이미 어겼으므로(WORKPLAN.md:142 Agent 도구로 리뷰) Agent 리뷰를 동등하게 인정하도록 고친다.
- **커밋 규약**: 99커밋 중 **32개(32%)가 "문서: WORKPLAN 표에 커밋 해시를 적는다" 1~2줄 커밋**(예 4ec6a60, 4261945). 원인은 '표에 해시'라는 규칙 자체 — 해시는 커밋 뒤에만 안다. 표에는 **날짜만**, 커밋 제목에 접두어 `[P3-05]`를 붙여 `git log --grep`으로 찾게 한다. 리뷰 통계(인정/기각 건수·변이 수)는 커밋 본문이나 CHANGELOG로.
- **현재 단계 추적**: `STATUS.md` 한 쪽(현재 단계·다음 3작업·열린 결정 Top 5·기준 해시·테스트 수)을 신설하고 CLAUDE.md '현재 단계'(약 34KB)·guideline §11 상태 줄(3922행 65KB)·WORKPLAN 부록 A는 CHANGELOG로 이관. effort·ultracode 지시는 WORKPLAN에만.
- **일정 단위**: 주 대신 '작업일(세션)'과 실측 표. 계획 대비 5~10배 빨랐던 코드와 달리 콘텐츠는 그렇지 않을 것이므로 Stage B부터 실측으로 재추정.

## 권장안
- [P0] **Playable MVP를 정의하고 'v0.8 예약'·서막보다 앞에 둔다** — 통치자 단일 모드·첫 생애 한 번·30~60분·끝 둘 이상(성공 T3 / 실패 폐위·붕괴 / AI 선점 시계)으로 MVP를 못 박고 WORKPLAN §3 표를 A1~A7(저장·결정 축·세계 손질·피드백·임시 엔딩·밀도·출하)로 다시 쓴다. 거리는 실측 속도로 12~18 작업일. 현 순서(v0.8 예약 11~15.5일 → 서막 1.5~2주)로는 플레이어가 결정을 내리는 빌드가 두 달 뒤다.
- [P0] **저장 작업을 MVP 첫 작업으로 당긴다** — §16 #33 ①②③·#70·#40 ⑦(자동 저장 트리거, 이어하기 슬롯 열거, 백업 슬롯, 머리·CRC, 연대기 상한)을 '단계 6 앞'이 아니라 지금. 근거: 게임 코드에서 SaveCurrentGalaxy/LoadGalaxy 호출 0건, 세이브 1MB 예산 초과(guideline.md:3716). 저장 없는 빌드는 플레이어블로 셀 수 없다.
- [P0] **임시 엔딩과 연대기 최소형으로 '판의 끝'을 만든다** — 엔딩 검사가 없고(RunHeadless 주석) KillPlayer가 해소되지 않는 지금(Sim cpp:2215-2228), 성공=내 백성 셋째 칸, 실패=폐위·붕괴, 시계=AI 백성 셋이 먼저 셋째 칸(§4.3 '다른 질서' 대용, 기존 EvaluateFeats로 공짜)을 임시 규칙으로 두고 Severity 2 줄+비문을 나열하는 연대기 화면을 만든다. 계승(4b)이 오면 실패 엔딩만 계승으로 교체되도록 표현 계층에 둔다.
- [P0] **통치자 결정 축 둘과 자동 일시정지를 넣는다** — 연구 중점 슬라이더(ResearchFocus는 상태에 있고 0.25 고정, 명령만 없음)와 카드 위젯 1개 + 청원 6~8장(첫 접촉·파벌 2·'왕좌를 지키겠는가'·헤롯 1). 카드 위젯은 뒤의 조우·서막·사자 카드가 전부 재사용한다. Severity 2 자동 일시정지 옵션(기본 켬)을 함께 — 첫 600틱 말해진 줄 9→25 목표의 절반이 여기서 온다. 선행: DT_Encounters 스키마와 make_data_tables 중첩 구조체 검사.
